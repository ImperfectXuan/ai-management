# Project: AI Workspace

This repository is the **AI Workspace infrastructure project** — a shared
layer that provides rules, conventions, skills, and project memory to
AI Coding tools.

## For AI Agents Working in This Repo

You are operating inside the AI Workspace project itself. Follow these
instructions when making changes:

### Navigation

- Canonical rules: `.ai-workspace/rules/`
- Tool adapters: `.ai-workspace/adapters/`
- Documentation: `docs/`

### Rules for Contributing

1. Never edit root-level tool stubs (`AGENTS.md`, `CLAUDE.md`) directly
   for content changes. These are generated.
2. When adding or modifying a rule, edit the canonical file in
   `.ai-workspace/rules/`.
3. When adding support for a new AI Coding tool, create a new directory
   under `.ai-workspace/adapters/` following the existing pattern.
4. Run `.ai-workspace/scripts/sync.sh` after any rule change.
5. Run `.ai-workspace/scripts/validate.sh` before committing.

### Code Conventions for This Repo

- All documentation is written in Markdown.
- Scripts are POSIX-compatible shell or widely-supported scripting languages.
- Directory names use kebab-case.
- Every directory contains a `.gitkeep` until it has real content.
- Frontmatter in `.md` files uses YAML.

### Architecture Constraints

- The `rules/` module must remain tool-agnostic. No tool-specific references
  in canonical rules.
- Adapter files must be under 50 lines. If an adapter grows beyond that,
  the canonical representation needs improvement.
- The sync script must be deterministic: same input → same output.

## For AI Agents Working in Projects That Use AI Workspace

When you encounter a project that includes a `.ai-workspace/` directory:

1. Load `.ai-workspace/rules/00-core.md` first — it contains the
   foundational rules for the project.
2. Load domain-specific rules from `.ai-workspace/rules/domains/` as
   relevant to your task.
3. Reference `.ai-workspace/memory/` for project context, architecture
   decisions, and technical history.
4. Follow `.ai-workspace/skills/` if you support skill definitions.
5. Treat the canonical rules as authoritative. Tool-specific files
   (`AGENTS.md`, `CLAUDE.md`, etc.) are derived and may lag.
