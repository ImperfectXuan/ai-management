> **测试对象**：`aiws sync` 三阶段（规则 → MCP → 技能）、`--tool/--scope/--only` 过滤、幂等性、漂移检测。

## 1. 目标

sync 是「规范层 → 工具原生文件」的核心闭环。本域验证：

## 3. 全量 sync

### 步骤 3.1 — 运行

```bash
$AIWS sync
```

**预期**：三段输出，依次为：

1. **规则**：`Syncing rules...` →
   - `Generated: cursor rules - 14 file(s) in .cursor/rules`
   - （若有记忆上下文）`Generated: cursor context - 00-context.mdc`
   - `Generated: trae rules - 14 file(s) in .trae/rules`
   - `Generated: CLAUDE.md (claude)`、`Generated: AGENTS.md (codex)`
2. **MCP**：`Syncing MCP configurations...` → `MCP synced: <tool> (project) -> ...`
3. **技能**：`Syncing skills...` → `Skills synced: <tool> (project) - 25 skill(s)`
4. 结尾 `[OK] Sync complete!`

**判定**：✅ 三阶段都执行、结尾 `Sync complete`；❌ 中途 `[ERROR]`。

### 步骤 3.2 — 检查产出文件

```bash
ls AGENTS.md CLAUDE.md .mcp.json .codex/config.toml .cursor/mcp.json .trae/mcp.json
echo "---- Cursor 规则数 ----"
ls .cursor/rules/*.mdc | wc -l
echo "---- Trae 规则数 ----"
ls .trae/rules/*.md | wc -l
echo "---- 技能链接 ----"
ls .cursor/skills 2>/dev/null | wc -l
```

**预期**：
- 根层 6 个文件都在。
- Cursor/Trae 规则文件各 14（8 核心 + 6 领域；若有 context 则多一个 `00-context`）。
- `.cursor/skills` 有 25 个链接。

**判定**：✅ 文件与数量符合预期。

### 步骤 3.3 — 生成文件带标记

```bash
head -1 CLAUDE.md
head -1 .cursor/rules/00-core.mdc
```

**预期**：均以 `<!-- Generated by AI Workspace - DO NOT EDIT MANUALLY -->`（cursor/trae 则在 frontmatter 内）开头。
**判定**：✅ 有「勿手动编辑」标记（这是漂移检测与 import 判定的依据）。

## 4. 过滤选项

### 步骤 4.1 — `--tool`（单工具）

```bash
$AIWS sync --tool cursor
```

**预期**：只同步 Cursor（规则 + MCP + 技能三阶段都只输出 `cursor` 相关行）。
**判定**：✅ 输出中不出现 `claude`/`codex`/`trae` 的生成行。

### 步骤 4.2 — `--scope project`（单 scope）

```bash
$AIWS sync --scope project
```

**预期**：MCP/技能只写 project scope（仓库内），不写 `~/.claude.json` 等 global 配置。
**判定**：✅ 无 global 输出。

### 步骤 4.3 — `--only rules`（单模块）

```bash
$AIWS sync --only rules
```

**预期**：只跑规则阶段，**跳过** MCP 与技能。
**判定**：✅ 无 `Syncing MCP` / `Syncing skills` 输出。

### 步骤 4.4 — 非法 `--only` 快速失败

```bash
$AIWS sync --only bogus; echo "退出码=$?"
```

**预期**：`Invalid --only value: bogus (expected: rules|mcp|skills)`，退出码 `1`。
**判定**：✅ 非法值被拒绝（fail-fast，不静默忽略）。

## 5. 幂等性

### 步骤 5.1 — 连续两次 sync，状态一致

```bash
$AIWS sync >/dev/null
$AIWS rules status; echo "退出码=$?"
```

**预期**：`规则与 manifest 一致（14 条）`，退出码 `0`。
**判定**：✅ sync 后规则与 manifest 一致（版本化检查点已落盘）。

### 步骤 5.2 — 重复 sync 不产生新改动

```bash
git status --short
```

**预期**：无输出（或只有你之前测试留下的改动；生成文件被忽略，不出现）。
**判定**：✅ 重复 sync 幂等，不产生脏 diff。

## 6. 漂移检测闭环

漂移 = 手动改了生成文件（或规范层变了却没 sync）。`validate --drift-strict` 能发现，`sync` 能修复。

### 步骤 6.1 — 制造漂移

```bash
# 手动往生成文件里塞一行（模拟「有人手改生成文件」）
echo "- 这行是手改的漂移内容" >> .cursor/rules/00-core.mdc
```

### 步骤 6.2 — 检测漂移

```bash
$AIWS validate --drift-strict; echo "退出码=$?"
```

**预期**：出现 `[ERROR] Generated files drifted from canonical rules (run: aiws sync)`，退出码 `1`。
**判定**：✅ 漂移被当作 error 捕获。

### 步骤 6.3 — sync 修复漂移

```bash
$AIWS sync >/dev/null
$AIWS validate --drift-strict; echo "退出码=$?"
```

**预期**：漂移消失，退出码 `0`（或仅剩 warning）。
**判定**：✅ sync 覆盖生成文件、消除漂移。

## 7. 模块开关

`workspace.json` 里 `skills.enabled: false` 会让 sync 跳过技能阶段并显式提示：

```bash
# 临时关闭技能模块（测完恢复）
jq '.skills.enabled = false' .ai-workspace/config/workspace.json > /tmp/ws.json && mv /tmp/ws.json .ai-workspace/config/workspace.json
$AIWS sync --only skills
jq '.skills.enabled = true' .ai-workspace/config/workspace.json > /tmp/ws.json && mv /tmp/ws.json .ai-workspace/config/workspace.json
```

**预期**：关闭时输出 `Skills module disabled (config/workspace.json skills.enabled=false). Skipping skills sync.`；恢复后再 sync 正常。
**判定**：✅ 模块开关生效，关闭时显式跳过（不静默）。

> ⚠️ 上面用 jq 原地改了 `workspace.json`（它是被 git 跟踪的文件），测完务必恢复为 `true`（第三条命令已做），并用 `git diff .ai-workspace/config/workspace.json` 确认无残留。
