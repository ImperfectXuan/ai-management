# 本机演示与版本快照

适用范围：macOS arm64；当前源码版 Desktop。演示人工收编与四工具项目级同步；AI 整理审核、跨项目复制与更新不在本轮演示范围。

## 启动

前置条件：Node.js 24、npm、Git、jq。首次安装依赖需要网络；演示过程不需要联网或真实凭据。

```sh
cd electron
npm ci
npm run demo
```

`demo` 先执行 TypeScript 检查和构建，再创建全新的临时环境并启动当前源码版应用。终端打印总库、两个来源项目和环境目录；目录里的 `演示路径.txt` 可直接复制路径。每次重新运行都会生成新环境，保留上次演示供检查。独立 HOME 和 Electron 用户目录隔离了真实全局配置与仓库列表。

请从 `npm run demo` 启动，避免误开 `electron/release/` 里的旧版本。若已打开其他源码版窗口，先退出后再运行，避免认错窗口。准备完成后可提前保留启动窗口，现场无需安装依赖。

## 10—15 分钟演示顺序

1. 工作区概览：确认“演示总库”，展示规则、技能和 MCP 管理入口。
2. 配置收编：终端打印的总库已预选；分别添加来源 A（cursor/project）、来源 B（trae/project）。来源均未安装 AI Workspace。
3. 开始扫描：展示同内容归为同一候选、同名不同内容标记冲突，以及 Skill 和 MCP 候选。
4. 审核：可批量“全选新增”；同名冲突必须逐项明确选择，样例建议“忽略”；若出现缺失 MCP 配置等“无法解析”项，也明确选择“忽略”。检查每个候选都有动作。
5. 生成计划：自动进入预览阶段；需要修改时点击“返回审核”。核对新增与忽略动作、目标位置、未解决项；未解决项非空时不得执行入库。
6. 执行入库：展示结果与入库记录。MCP 为虚构配置，仅演示配置分发，不启动真实 MCP 服务。
7. 工作区概览“同步到四个工具”：展示进度。四工具规则、context 和技能均经共享 CLI 同步，默认仅写项目范围。
8. 差异页：选择 Cursor 的 `00-core`，同步后应无差异；手动改生成文件后可见真实漂移，再同步可恢复。预期产物在临时目录生成，对比不会改动总库。
9. 密钥页：显示 vault 未初始化，不触发解密，也不会把读取失败伪装成未初始化。
10. 配置收编页展开“入库记录”：执行本批次回退，展示规范资产恢复。回退只针对入库批次，不回滚已经分发的工具原生文件；需要另行处理生成产物，勿宣称全工具事务回退。

## 演示前验证

```sh
cd electron
npm run typecheck
npm test
npm run build
npm run demo:verify
```

`demo:verify` 连续执行两轮全新夹具旅程，使用真实 CLI 引擎：扫描 → 比较 → 人工决定 → 计划 → 入库 → 幂等重试 → 四工具同步 → validate → 密钥只读 → 历史 → 回退。断言来源内容不变、默认不写全局目录。它是集成验证，不能代替原生 Electron GUI 的逐项验收。

CLI 备用入口在终端打印的总库下：

```sh
cd <总库路径>
.ai-workspace/scripts/aiws sync --scope project
.ai-workspace/scripts/aiws validate
```

同步取消会终止 CLI 进程组并报告取消；已经完成的文件写入不会自动回滚，重新同步可收敛。错误和取消不会写入“本次同步成功”时间戳。

## 冻结当前实现

```sh
cd electron
npm run demo:freeze
```

输出保存到被 Git 忽略的 `electron/release/demo-source-*/`，包含源码归档、SHA-256 校验文件和 `manifest.json`。清单记录基准 commit、未提交状态、运行时、逐文件内容哈希与权限，包含尚未跟踪的新实现。采用白名单，不收集 vault、真实 MCP、已有收编批次、用户全局配置或 `node_modules`。此操作不执行 Git 提交或推送。

复现时先核对归档旁的 `.sha256`，解压后执行 `node source/electron/demo/verify-snapshot.mjs manifest.json` 校验逐文件内容和权限，再进入 `source/electron`，执行 `npm ci`、`npm test`、`npm run demo`。打包归档不会自动证明通过验收；应使用本次验证记录对应的快照。依赖按 lockfile 安装，需要网络；同一机器现场演示应提前装好。
