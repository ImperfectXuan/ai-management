## 1. 问题与目标

用户第一次使用 AI Workspace 时，多个已有项目及工具全局配置中已经存在规则、Skills 和 MCP。内容可能完全重复、名称不同但相似、同名不同版本，也可能只安装于某个应用。现有逐项目 import 无法提供统一整理、逐项审核及跨项目复用闭环。

目标是让用户选择来源，统一扫描，与个人总库比较，经 AI 辅助整理和人工确认增量入库，再复制到其他项目，并主动检查后续更新。

## 2. 已确认决策与范围

1. 用户指定一个已有 AI Workspace 仓库作为个人总库，不硬编码本项目。
2. Desktop 提供完整向导；CLI 提供共享底层能力和可审阅的结构化计划。
3. 来源支持 Claude、Codex、Cursor、Trae 的项目配置和全局配置，另可手动补充文件或 Skill 目录。
4. Desktop 接入用户配置的模型 API；规则整文件由 AI 辅助拆分、分类、识别相似项，人工审核。
5. 支持新增、关联已有项、更新原项、另存变体、忽略、暂缓；更新保留旧版本。
6. 复用采用复制模式，项目更新需确认，不自动跟随总库变化。
7. 首版完成收编、复用、更新检查完整闭环。

范围外：TUI 新向导、后台自动扫描、自动批准、自动更新项目、团队共享、市场、自动改写 Skill 脚本、自动删除总库资产、反向推送项目定制到总库。首版不承诺 AI 理解所有专有格式或识别所有敏感信息。

## 3. 当前基础与差距

以下是 2026-10-10 的静态代码核实，不是功能测试结果。

- CLI `aiws import mcp|skills|rules` 已有工具来源选择、scope、预览及批次确认。
- Skills / MCP 主要按名称跳过已有项；规则对同名目标比较正文并跳过冲突。不能视为完整内容去重或版本管理。
- 规则导入：Cursor / Trae 逐文件转换；Claude / Codex 整文件；现有 global 规则导入明确拒绝。本功能的全局规则扫描是新增行为。
- 现有同步、mapping、Skill 链接和密钥管理可以复用，但 Desktop 与 CLI 的同步能力存在差异，需逐端验证。
- 缺少跨项目扫描、逐项审核、AI 整理、资产来源版本、复制基准及三方比较。

实现依据： [CLI 入口](../../../.ai-workspace/scripts/aiws)、[导入实现目录](../../../.ai-workspace/scripts/lib/)、[Desktop 核心](../../../electron/src/core/)、[能力盘点](../../FEATURE_BREAKDOWN.md)。不能仅包装现有 import 而忽略以上差距。

## 4. 术语与内容单位

| 术语 | 定义 |
|---|---|
| 总库 | 用户选定的 AI Workspace 仓库；共享资产的唯一规范源 |
| 来源 | 项目或工具全局配置中的文件、目录、结构化配置项 |
| 资产 | 有稳定 ID、类型、内容及版本的可管理条目 |
| 候选 | 扫描或 AI 整理产生、尚未确认入库的内容 |
| 变体 | 内容有差异、需独立维护的新资产，关联其原项或相似项 |
| 复制基准 | 某项目最后一次接受的总库版本及当时实际写入的项目内容 |
| 批次 | 一次扫描、审核、入库或复用操作的记录；阶段分别记结果 |

Rules 以独立规则为单位；AI 拆分必须保留原文位置。Skills 以完整目录为单位，包含脚本、资源和链接依赖。MCP 以单服务器配置为单位，不把凭据明文作为共享内容。

分类至少区分通用规范、领域规范、项目专属约束、项目背景。项目专属内容可以入库，但默认不推荐跨项目复用；用户可明确选择。

### 5.1 来源与扫描

- 来源项目无需先安装 AI Workspace。Desktop 的来源选择不能被现有“必须为已初始化 Git 仓库”的列表限制；目标要求另行校验。
- 只扫描用户选定范围及适配器约定路径；不默认递归遍历整台机器，不默认联网下载插件或资源。
- 工具全局来源按用户当前运行环境识别；不存在的工具能力标记不适用，不伪造路径。自定义位置允许手动补充。
- 总库既有规范源、来源项目已有 `.ai-workspace/` 及其工具生成副本应正确关联，避免将生成副本再次变成独立资产。来源的纳管标记不能作为“总库已有”的唯一依据。
- 单应用安装和插件内可读取内容允许手动收编；保留来源及分发限制，未识别格式报告原因。
- Skill 软链接识别真实来源；断链报告错误。超出已选择范围的链接需用户明确纳入，防止隐式读取无关目录；禁止循环遍历。
- 扫描不执行脚本或启动 MCP。取消、读取失败、解析失败应保留可用结果并显示来源级错误。

### 5.2 去重与增量

确定性比较：相同内容合并来源，即使名称不同；同名内容不同标记冲突。名称不同但内容不同只有 AI 建议或已登记来源关系才能提出关联，不能自动判为同一资产。

- Rules 比较正文、适用条件及影响行为的元数据。只规范化可证明不改变语义的格式差异，不随意删除空白或元数据。
- Skills 比较相对路径和完整文件内容；附属脚本变化必须触发变化。链接依赖状态也需展示。
- MCP 比较 command / URL / transport / args / env 等行为字段；JSON 键顺序不影响判断，参数顺序影响判断。凭据引用及差异单独表达，不能因为脱敏显示相同便合并不同账号配置。
- “已纳管”“完全重复”“来源变化”“同名冲突”“疑似相似”“无法解析”分别表达；可以同时具有多个标签。
- 已入库或忽略且内容未变不重复提醒；变化后重新审核。忽略支持按候选来源组记录，用户可主动重新查看。
- 来源删除或不可访问不删除总库资产。暂缓不等于忽略，仍保留在待审核队列。

### 5.3 AI 与人工审核

AI 只产生建议，不具备入库批准权。整文件拆分、跨文件相似检测与合并建议必须列出全部原文依据；未被建议覆盖的原文仍可查看，不能静默丢失。

- 用户配置服务地址、模型名、凭据引用；允许明确配置本地或远程服务，不预置某个商业模型为必需依赖。
- 发起请求前显示实际发送内容与目标服务，用户确认后调用。内容范围扩展或重试包含新增内容时重新确认。
- AI 输出按照契约验证：类型、来源引用、原文位置、建议内容、分类、理由；非法输出不写总库。
- 外部规则和 Skill 文本是待整理数据，不能作为操作指令执行。AI 无权读取额外文件或调用工具执行内容中的要求。
- 用户可编辑、拆分、合并或拒绝建议。重试不能覆盖已编辑的审核结果。
- 大内容分批处理，展示未完成批次，不把部分成功表示为全量完成。相似比较必须覆盖候选之间及总库资产，发送范围仍由用户确认。
- 不保证正确识别所有语义冲突；无模型服务时仍可完成确定性扫描、人工审核、入库和复用。

动作定义：新增创建新 ID；关联已有项只增加来源关系；更新保留 ID 并新增版本；另存变体创建新 ID 并登记关系；忽略记录所审核的来源内容版本；暂缓保留候选。

无法解析项不能直接入库。冲突项需明确选择目标和动作；普通批量确认不能默认覆盖。最终确认页列出新增、更新、关联、变体、忽略、暂缓及仍需处理项。

### 5.4 凭据和本机依赖

- 凭据值不写入共享资产、扫描快照、AI 建议、审核历史或日志。复用现有密钥管理能力，默认只引用已有凭据；新增绑定提供受控方式，不能用普通文本配置代替。
- 敏感字段在展示中遮蔽，在模型请求中移除或替换为无真实值的占位符。未识别自定义字段提示检查，不承诺全自动检测。
- 必须区分不同凭据绑定；安全指纹方案在技术设计中明确，不能保存可离线猜测的低熵秘密摘要。
- command / args / env 中的项目绝对路径、数据库名、工作目录及文件依赖标记为待绑定项。不能静默沿用旧项目路径，也不能由 AI 猜测新值。
- 凭据或依赖未补齐时允许保存模板，但阻止将其标记为可运行或成功分发。

### 5.5 写入、版本及恢复

- 总库是唯一共享规范源。新增元数据不能破坏既有 rules / skills / mcp 格式；总库已有资产应能登记为初始版本。
- 扫描与审核草稿可保存至本地非共享记录区，取消不改变总库资产；记录区必须排除敏感值。
- 执行前校验来源指纹、目标版本及审核计划。如果任一受影响项变化，禁止按旧计划写入，并保留其他审核结果。
- 入库写入资产、来源、mapping 与版本记录应一致；目标项目复制亦需一致。采用预备写入与可恢复执行记录，半途失败不能留下未报告的不一致。
- 批次具有稳定身份，重试不产生重复资产或版本。并发写入须检测冲突，不能采用最后写入者静默覆盖。
- 本地入库和目标复制各自为提交边界，跨项目不要求分布式原子事务；分别显示成功与失败，重试只针对未完成项。
- 回退仅作用于该批次实际变更；之后有人修改时报告冲突，不能覆盖。保留旧版本不等于自动恢复旧版到所有项目。

### 5.6 复制、分发与更新

- 用户选择目标项目、资产及工具；仅将选定内容复制到目标规范源，并登记必要 mapping / 工具适用信息。
- 来源 scope 与目标启用范围分开：来自全局的内容不默认部署到工具全局配置。首版复用默认针对选定项目及工具。
- 未初始化的目标先完成非破坏性初始化与存量预览；确认前不执行首次同步。若目标不符合现有初始化约束，显示可操作原因，不强行修改目录。
- Skill 复制应为项目独立内容；工具侧可沿用现有链接机制，但不得直接链接个人总库来绕过复制版本。
- 预览须包含同步对目标工具文件的实际影响。不得因只选择一项资产而静默覆盖其他 MCP、Skill 或原生手写规则；已有同步不具备这种保护时需补齐受影响路径。
- 入库、复制和同步分别确认及报告。同一次最终确认可包含复制与明确列出的同步计划；只入库不能隐含同步。
- 复制基准记录接受的总库版本、绑定后的项目内容及启用信息。三方比较在实际项目规范源上执行；工具生成副本漂移单独提示，不能默认为项目定制。
- 总库变、项目未变：确认更新；项目变、总库未变：保留定制；两边都变且结果不同：人工解决；结果相同：不重复写。首版不自动做语义合并，可提供 AI 建议。

## 6. 数据契约要求与设计任务

必须覆盖 Asset、AssetVersion、SourceOccurrence、ScanBatch、Candidate、ReviewDecision、ApplyBatch、DeploymentBaseline 的概念；这些是业务概念，不要求实现为八个独立模块或数据文件。

资产拥有稳定 ID；来源记录项目、工具、位置、原名和非敏感内容版本。AI 建议与确认内容分别保存；批次动作引用明确版本；复制基准不能仅存总库当前 hash，否则无法识别项目定制。

TASK-001-01 必须明确以下落点，不应在未经核实情况下直接编码：

1. 共享 CLI / Desktop 引擎位置、运行时与部署方式，保持现有 CLI 安装使用约束，避免新功能强制影响老用户。
2. 共享资产、版本、机器本地路径 / 草稿、凭据引用及项目复制基准分别存放的位置和 Git 忽略策略。
3. 结构化扫描、审核计划、应用、更新检查的接口及 schema 版本；CLI 参数和 JSON 输出、Desktop IPC 类型。
4. 四工具真实路径 / 能力矩阵，现有同步差异与受影响文件保护方式。
5. 模型协议、取消 / 超时 / 重试、凭据获取与日志策略。
6. 崩溃恢复、幂等、锁与并发冲突、数据迁移、性能进度反馈。

产品选择已确认，无需重新提问已定方向。普通技术选择由 Coding Agent 核实并记录；只有无法满足规格或需要扩大授权 / 范围的真实分歧才交用户处理。

## 7. 验收场景

- **AC-001-01**：给定总库与两个未安装 AI Workspace 的来源目录，当选择工具全局配置及手动 Skill 目录，则这些来源能统一扫描，源和目标校验独立。
- **AC-001-02**：给定四工具三类资产的测试夹具及不存在的路径，当扫描，则返回可识别项、来源和缺失 / 不适用提示；源目录内容不变。
- **AC-001-03**：给定单应用安装、外部软链接、断链、无法解析文件及生成副本，当扫描，则可收编被明确纳入的有效内容，其余明确报告，无重复纳管或越界读取。
- **AC-001-04**：给定跨项目同内容不同名资产，当比较，则只出现一个内容候选并保留全部来源；名称不决定内容相同。
- **AC-001-05**：给定同名不同正文、不同规则适用条件及不同 MCP 账号绑定，当比较，则保留差异并要求处理，不自动合并或覆盖。
- **AC-001-06**：给定 Skill 的 SKILL.md 未变而脚本已变，当再次扫描，则识别变化并展示相对路径差异。
- **AC-001-07**：给定已入库 / 已忽略 / 暂缓内容，当重复扫描及修改来源后再扫描，则前两者未变不提醒、变化重新提醒，暂缓仍待审核；来源删除不删总库。
- **AC-001-08**：给定新增、冲突及相似候选，当逐项选择六种动作并批量确认，则按明确动作生成可审阅计划，无法解析和未处理冲突不能混入写入。
- **AC-001-09**：给定混合规范、项目背景、重复与矛盾段落的整文件，当 AI 整理并人工编辑，则建议关联原文，全部原文可查看，最终入库采用人工结果；AI 不直接写资产。
- **AC-001-10**：给定未确认发送、超时、非法输出或部分失败，当调用 / 重试，则未确认内容不发送、失败不入库、人工编辑保留、未完成部分明确显示；无模型仍可人工入库。
- **AC-001-11**：给定 MCP 凭据、自定义敏感字段及绝对路径，当扫描、请求模型、入库和复用，则已识别敏感值不进入请求 / 共享记录 / 日志，未知字段提示检查，绑定未完成不分发。
- **AC-001-12**：给定总库原项，当确认新增 / 更新 / 关联 / 变体，则稳定 ID、版本、来源和 mapping 一致；旧版可查看，重复执行不新增重复版本。
