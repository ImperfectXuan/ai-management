# 001 · Coding Agent 交接 prompts

## 使用方法

按步骤 01～10 依次执行。每次把“通用约束”及对应步骤 prompt 一起发送给 Coding Agent；新会话同样需要通用约束。不要一次把十步全部作为立即执行任务。

规格唯一来源：[spec.md](spec.md)。任务定义：[tasks.md](tasks.md)。实际验证：[verification.md](verification.md)。进度唯一入口：[PROGRESS](../../PROGRESS.md)。

步骤 01 仅做设计；02～10 授权实现对应任务和必要测试。每步完成后报告结果，用户再发下一步。任务划分不授权自动 commit、push、发布或真实模型付费调用。

## 通用约束（每步都附上）

```text
你在 /Users/xuanyi/Documents/AI-management 工作，实施“001 多项目存量资产收编与复用”。
请先读取并遵循 AGENTS.md，以及：
- docs/SDD.md
- docs/specs/001-asset-intake/spec.md
- docs/specs/001-asset-intake/tasks.md
- docs/specs/001-asset-intake/verification.md
若已存在 design.md，必须读取它；结合 docs/PROGRESS.md 检查前置任务的实际完成证据。

只执行本次指定 TASK，不提前执行后续任务。方向已经确定：指定仓库为总库、Desktop 为主要入口、CLI 共享底层能力、四工具及手动来源、API 辅助整理且人工批准、允许确认更新、复制复用和主动检查更新。不要重新询问这些选择。

开始前检查 git status。仓库存在既有未提交改动，逐项保护，不回退、不覆盖、不顺带整理。若 .codegraph/ 存在，理解或定位代码时先用 CodeGraph。代码与文档保持中文说明和仓库既有风格。

以现有实现为依据，不能把文档中的“已有”当成新规格全部满足。扫描、比较、审核和执行采用共享业务契约；禁止 Desktop 和 CLI 各自实现不同规则。兼容现有 import / sync / validate，不为原工作流强制新增模型服务前置。

来源只能在用户选定范围内只读处理。测试使用临时来源、总库、目标与 HOME / 工具配置夹具；不要扫描或同步我的真实全局配置，不调用真实模型服务、不执行 Skill 或启动 MCP。需要真实服务验证时先准备模拟验证与具体步骤，单独说明所需操作。

为实际行为和跨边界协作编写有意义的测试；不 mock 自己拥有的内部模块，不为文档或简单格式变化编写无意义测试。按任务完成条件验证，不虚构结果。适用端未验证则保留未执行状态。

普通工程决策核实后自行记录并推进；只有规格冲突、无法满足的约束或需扩大授权时提问。接口和存储选择记录在 design.md，不在 spec 中悄悄降低验收标准。

更新 PROGRESS 中对应 TASK 状态；verification.md 只记录真实验证及覆盖边界，局部检查不能代替整项 AC 通过。不要自动 commit、push 或发布。

结束时用中文报告：本任务交付、修改文件、验证命令与结果、未验证/遗留项、前置条件是否已满足；不要声称后续步骤已经完成。
```

## 步骤 01 · 核实技术设计

```text
请执行 TASK-001-01，仅做代码调查与技术设计，不修改实现代码。

核实 spec §3 的现有能力与 §6 的全部设计事项，重点检查四工具真实项目/全局路径、生成内容来源关系、Skill 链接、MCP 原配置保留、Desktop 单文件规则同步、未初始化来源/目标差异和现有预览是否写文件。

创建 docs/specs/001-asset-intake/design.md，确定共享引擎与运行时、schema 与 CLI/IPC 接口、资产稳定 ID 与版本、来源及忽略记录、元数据共享/本地边界、凭据身份与绑定、复制基准、执行锁/幂等/崩溃恢复、模型请求与输出契约。

列出四工具三类资产的能力矩阵，以及 AC-001-01～20 对应的设计章节。区分现有可复用能力、必须补齐的缺口与首版不支持内容。评估 CLI 的 POSIX sh+jq+age 使用约束，不能无解释地引入必需 Node 运行时。

必要时只调整 tasks.md 的工程粒度/依赖，不改变产品范围；记录真实阻塞问题。技术选择有依据就推进，不把普通方案选择变成强制用户审批。

验证文档链接、契约完整性和任务覆盖即可，不运行功能写入。报告设计结论与步骤02能否开始。
```

## 步骤 02 · 实现只读多来源扫描

```text
请执行 TASK-001-02，依照 design.md 实现共享扫描能力及 CLI 扫描预览，暂不实现入库或 Desktop 页面。

支持显式总库、多个来源项目、Claude/Codex/Cursor/Trae 全局配置及手动文件/Skill目录；未初始化来源也可扫描。按真实适配器读取 Rules、完整 Skills、单服务器 MCP。输出 schema 版本、来源位置、资产候选、读取/解析错误、进度与取消结果。

正确处理已纳管来源与生成副本、单应用安装、软链接真实来源、断链/循环及超出范围链接。不能用“有 managed 标记”直接认定总库已经拥有。形成持久候选之前分离已识别凭据，未知敏感字段提示人工检查；不得保存明文密钥或执行来源脚本。

用临时夹具覆盖 AC-001-01、02、03 和本任务负责的 AC-001-11 扫描边界。比较扫描前后来源内容，证明只读；CLI 预览不能创建总库资产。完善 design 的实际适配器差异，记录本步验证。
```

## 步骤 03 · 实现去重和增量判断

```text
请执行 TASK-001-03，复用步骤02候选契约，实现确定性比较、来源关系与增量决定，暂不执行资产入库。

比较总库已有资产及同批候选：完全相同内容合并来源，同名不同内容保留冲突，不同名不同内容不能自动关联。Rules 保留适用条件差异；Skills 比较所有相对路径及文件内容；MCP 规范化对象键但保留参数顺序、行为字段与凭据身份差异。

建立入库/忽略决定所对应的来源版本，暂缓保持待审核。未变不重复提醒，变化后重新审核；来源删除或暂时不可访问不删总库。总库既有规范源也能参与比较，不要求先重建库。

覆盖 AC-001-04～07：跨名完全重复、同名冲突、规则条件变化、Skill附属脚本变化、MCP参数及账号差异、重复扫描、忽略后变化、暂缓及来源删除。敏感值不能出现在持久指纹材料或日志中；安全凭据身份按 design 执行。报告分类规则和测试证据。
```

## 步骤 04 · 实现人工计划与增量入库

```text
请执行 TASK-001-04，建立共享人工审核计划和 CLI 预览/应用能力，不制作 Desktop 页面或 AI 调用。

支持新增、关联已有项、更新原项、另存变体、忽略、暂缓；非法或未处理冲突不能进入写入。预览列出每项动作、来源版本、目标版本及实际写入影响。应用必须使用明确审核计划，扫描不能自动批准。

实现稳定 ID、初始版本纳管、历史版本、来源关联和必要 mapping 登记；应用前复核来源及目标指纹。增加批次幂等、并发冲突检测、预备写入/执行记录、崩溃恢复及回退后续修改保护。不得把版本文件存在视为恢复机制已完成。

通过临时总库及故障注入覆盖 AC-001-08、12、13、14、19 的引擎部分，回归受影响的现有 import（AC-001-20 部分）。验证重试无重复、半途失败可恢复、回退不覆盖后续修改。分别记录局部结果，不提前标整项GUI验收通过。
```

## 步骤 05 · 实现 Desktop 非 AI 收编向导

```text
请执行 TASK-001-05，通过类型化 IPC 接入步骤02～04的共享引擎，完成 Desktop 非 AI 收编闭环。

提供总库选择、多项目/全局/手动来源选择、进度与取消、候选分类、全部来源详情、原文/差异、六种动作、冲突明确处理、批量确认、最终计划预览、入库结果与记录。来源选择不能被现有已初始化Git仓库列表限制。保持现有视觉和交互模式。

无模型配置仍可完成扫描→人工审核→入库；AI入口可留可解释的未配置状态，不加入假模型结果。取消不批准入库，过期计划保留用户其他编辑并引导重审。未处理冲突不能被“全选新增”绕过。

组件/IPC集成覆盖 AC-001-01、02、08、12、13、19 的UI路径，并使用临时夹具实际走一次Desktop流程。不能只依赖截图证明文件未修改或入库一致。记录具体观察和非AI闭环完成证据。
```

## 步骤 06 · 实现模型服务与建议契约

```text
请执行 TASK-001-06，实现可配置的模型 API 边界和结构化建议能力，暂不制作完整AI编辑工作台。

遵循design中已选协议，配置服务地址、模型名、凭据引用；调用前展示实际发送内容和目标服务，经用户确认后发送。比较范围包含用户选定候选及总库资产，范围扩展需要重新确认；大请求分批显示完成度。

实现结构化输出校验，检查来源ID、原文锚点、建议类型、内容、分类与理由。外部内容仅作数据，不授予工具执行权。凭据必须在请求组装前过滤，未知字段可由用户检查并排除。请求/错误日志不能含秘密或完整敏感响应。

覆盖 AC-001-09～11 的服务边界：未确认发送、范围变化、无效JSON/来源引用、超时、取消、部分失败、重试及密钥泄漏检查。自动测试mock模型服务这一外部边界，不调用我的真实模型或产生费用。失败保留扫描与人工状态，不存在直接入库通道。
```

## 步骤 07 · 实现 Desktop AI 整理与审核

```text
请执行 TASK-001-07，在现有收编向导中接入AI建议审核，继续复用同一人工计划与入库引擎。

展示整文件拆分、通用/领域/项目约束/背景分类、原文位置、全部原文、候选间及总库相似项、合并理由和矛盾提示。未被建议覆盖的段落不能从用户视野消失。

允许编辑、拆分、合并、接受、拒绝、暂缓建议；项目专属内容默认不推荐跨项目复用。Skills保持完整目录、不自动改脚本；MCP不让模型猜测配置或凭据。重试保存人工修改，新的模型结果供对照，不静默覆盖。

用可重复模拟模型响应覆盖 AC-001-08～10 的UI行为，并完整走一次“混合规则→拆分→人工修改→最终确认→入库”。验证入库内容来自人工确认版本、拒绝建议没有入库。实际模型验证如必要，先交付准备好的操作步骤，再请求真实调用授权。
```

## 步骤 08 · 实现复制、更新及安全同步引擎

```text
请执行 TASK-001-08，实现CLI/共享引擎的跨项目复用、更新检查和受保护分发，暂不制作复用页面。

选定资产、项目和工具后生成可审阅复制与同步计划，独立复制到目标.ai-workspace并登记mapping、工具启用与复制基准。总库不被直接链接到项目；全局来源不隐含全局部署。MCP凭据/路径必须显式绑定，未完成不分发。

目标未初始化时先非破坏性初始化预览和存量保护，首次同步必须经过审核。检查现有同步是否会覆盖未选MCP、手写规则或其他原生内容，补齐受影响路径保护；不能只保护.ai-workspace却覆盖工具文件。

三方比较使用接受的总库版本、当时实际写入的项目内容和项目当前内容；考虑MCP重绑定、项目定制及工具生成副本漂移。覆盖总库单变、项目单变、双方不同变、双方结果相同；不自动接受语义合并。

覆盖 AC-001-11、15～20 的引擎部分，包括两个目标、工具选择、独立副本、未初始化目标、未选内容保留、过期计划、复制/同步分阶段失败和幂等重试。沿用已有规则/Skill/MCP实际格式和同步机制，补齐明确缺口而非另造不兼容格式。
```

按当前仓库实际测试入口运行适用CLI、Desktop、TUI回归及构建/类型检查，不照搬历史计划。人工检查使用临时来源、总库、目标及工具配置；未测端/环境写清楚。失败修复后只重跑受影响验证和必要回归。

报告是否达到首版完成条件；有未执行或遗留项则明确其影响和下一步，不虚构全部通过。不要自动commit、push、发布或扩大至范围外功能。
