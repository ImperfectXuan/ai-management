## 1. 问题与目标

维护者现在只能在自己的 macOS 应用里维护一份本机内容库，再同步到 Claude、Codex、Cursor、Trae。团队没有共同的规范仓库，也不能审核后再并入。

目标：保留现有 macOS 本地应用，另加团队协作网页。团队规范仍在 Git 仓库。个人内容仍在本机内容库。两边隔离：个人手动把团队内容拉成本机副本，也可以从本机选出内容提交给团队；并入团队必须经过变更集审核。

第一期只覆盖 macOS 本地应用和网页。Windows 本地应用不在本包。

## 2. 范围与兼容边界

- 网页：一个账号加入多个团队；成员、审核者、所有者；阅读团队仓库；审核变更集；管理成员与角色。
- macOS 应用：从个人内容库提交变更集；手动从团队拉到个人库；在拉过的内容有新版本时展示提醒。同步到四个工具仍用现有应用能力。
- 可提交、可拉取的类型：规则、技能、MCP 定义。
- 范围外：
  - Windows 安装包与 Windows 真机同步（二期）。
  - 用网页代替本地应用，或由网页把文件写入成员电脑。
  - 自动拉取、自动覆盖个人副本、按团队版本持续改写个人文件。
  - 在网页里直接编辑团队文件。
  - 密钥明文、vault 文件、团队共享保险库。变更集中的 `${secret:NAME}` 占位符可以保留。
  - 记忆、global 范围安装、收编向导、技能市场。
  - CLI / TUI 行为变化。
- 现有 macOS 同步、规则编辑、内容库与应用项目的行为保持不变，除非本包的拉取与提交明确写入个人库。

## 4. 验收场景

- **AC-003-01**：给定一个账号，加入团队 A 和团队 B 后，两边的成员身份与仓库内容互不混用。
- **AC-003-02**：给定成员账号，不能通过或退回变更集，也不能增删成员。给定审核者，可以通过或退回变更集，不能增删成员。给定所有者，可以增删成员并设置这三种角色。
- **AC-003-03**：给定团队仓库中的一条规则，网页展示的内容与该仓库当前提交一致。审核通过产生新的团队仓库提交，而不是只改网页数据库里的正文。
- **AC-003-04**：给定个人库中的规则、技能和 MCP，成员一次提交为一个变更集；审核页能看到这三项相对团队当前内容的差异。
- **AC-003-05**：给定变更集中含 vault 文件、密钥明文，或 MCP 字段里有非 `${secret:NAME}` 的凭据值，提交被拒绝，团队仓库无新提交。只含占位符的 MCP 可以提交。
- **AC-003-06**：给定待审变更集，审核者退回后团队仓库不变。通过后，集内条目全部出现在同一次团队提交中。
- **AC-003-07**：给定提交后、通过前，团队仓库里同一条目已由另一次通过的变更改变，则本次通过失败，团队仓库不写入这一集的部分内容，提交者可再次提交。
- **AC-003-08**：给定成员提交的变更集只改规则正文，通过后该成员的角色不变。
- **AC-003-09**：给定团队有更新且用户未点击拉取，个人库文件保持原样，现有同步不会把未拉取的团队内容写入工具文件。
- **AC-003-10**：给定个人库已有同名规则，拉取时默认留下原文件并另存团队副本；只有用户明确选择覆盖时才替换原文件。覆盖前能区分哪一份会被替换。
- **AC-003-11**：给定用户从团队某版本拉过一条规则，该规则在团队仓库被新提交修改后，macOS 应用展示这条规则可更新。用户不操作时，个人副本字节不变。
- **AC-003-12**：给定只记录了回执，回执与提醒中不含规则正文以外的密钥、token 或 vault 内容。
- **AC-003-13**：给定用户从未拉过的团队新规则，macOS 应用不为此发提醒。用户仍可在应用中浏览并手动拉取。
- **AC-003-14**：给定网页会话，不存在把团队文件写入成员电脑或触发本机 sync 的操作。成员需要工具生效时，仍在 macOS 应用中对个人库执行现有同步。
