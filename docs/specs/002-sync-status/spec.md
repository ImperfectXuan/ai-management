## 1. 问题与目标

基线 `81195b47728bd5d99fe6609db83e793c7f1d0fe4` 已将用户选定的统一内容库与应用项目分离。规则、Skills、MCP 均从内容库管理，再向另选的项目分发。

当前 Desktop 概览仍使用组件内 `syncState`，成功后更新项目级 `lastSyncAt`；规则页已移除 `dirty`，有目标项目即可重同步。这些数据不能说明某个内容库版本是否已分发到某个工具和模块，切页、重启及切换内容库后也缺少可靠依据。

目标：用户能够看到每个分发单元是否有成功同步当前来源版本的记录，以及最近一次操作是否失败、取消或中断。版本记录不证明目标文件当前一致，不证明 MCP 服务在线。

## 2. 范围与兼容边界

- 首版用户入口为 Desktop：概览、规则、Skills、同步全部与托盘；MCP 修改、收编和回退会触发状态重算。
- 共享 CLI 增加供 Desktop 使用的结构化执行回执。CLI/TUI 的既有调用方式保持兼容；独立 CLI/TUI 执行不写 Desktop 私有记录，Desktop 不据此推测成功。
- 默认 project；已有显式 global 操作按真实全局目标隔离，不能给项目记录成功。规则仅 project。
- 单项 Skill 链接/卸载也纳入：单项操作不能将整个 Skills 模块标为已同步。
- 范围外：后台文件监控、自动同步、实时目标内容比较、MCP 健康检查、跨机器共享状态、完整复制/更新/清理引擎。
- 本包不修改当前生成、备份和删除语义。模块无内容而跳过时不能凭空宣称旧产物已清理；遗留处理边界见设计 §4。

## 4. 验收场景

- **AC-002-01**：给定同一库与两个项目，仅同步项目 A 的 Cursor 规则，则项目 B、Trae、MCP、Skills 的成功基线均不改变；只切换视图也不改变记录。
- **AC-002-02**：给定库 A 已成功同步，切到库 B 不复用 A 的成功记录，切回 A 可查看 A 的历史记录，不绕过期间的覆盖失效。global Skills 不归属某个项目；Codex/Claude 共用 `.agents/skills` 时，同库、同目标、同有效计划的完整同步及重复同步后，两者均可为 current；工具仍保留各自执行记录，不替未执行工具创建成功基线。
- **AC-002-03**：给定成功基线，修改适用规则正文、当前工具 required、context、Skill 附属脚本或有效 MCP 本地覆盖，则仅受影响单元变为待同步；删除输入同样能被识别。
- **AC-002-04**：给定相同输入，目录枚举或 MCP 对象键顺序变化不改变指纹；MCP 参数数组换序改变指纹。修改 rules manifest/CHANGELOG、无关 ADR 或不适用工具规则不影响本单元。
- **AC-002-05**：给定内容未变，实际相关生成器依赖或指纹算法版本变化后，受影响单元需要重新同步；不依赖始终未变的 package 版本号。
- **AC-002-06**：给定成功记录，关闭并重启应用，所选库/项目/工具/模块的状态可恢复；源文件在应用关闭时改变，首次查询即显示待同步。
- **AC-002-07**：给定仅有旧 `lastSyncAt`，升级后显示未记录，不补造成功记录；目录别名去重、移走目录或换路径分别按设计的身份规则处理。
- **AC-002-08**：给定模块实际完成，只有有效回执、输入复核及成功记录原子落盘全部完成后显示已同步；同内容重复同步不误标其他单元。
- **AC-002-09**：给定模块禁用、工具不支持、缺依赖、缺 mapping、无内容或凭据处理被跳过，即使 CLI 退出 0 也不记录成功；最后一项资产删除后，界面不宣称旧目标已清理。
- **AC-002-10**：给定已有成功记录，在相同来源版本上重试并失败或取消，原成功记录仍可查看，但当前状态显示需重新同步及最近失败/取消，不出现绿色已同步。
- **AC-002-11**：给定批次前几个单元成功、后续单元失败或取消，已完成且落盘单元保留历史成功；无输出重叠的单元保持原版本状态，与失败写入共享输出的单元保持 pending。当前单元无新基线，未开始单元不被标为失败或成功，但已有记录可因物理目标被写入而失效。
- **AC-002-12**：给定持久化 running 后进程异常退出，重启显示中断、需重新同步；状态文件损坏/未知版本/不可写时明确报错，不伪装成空记录或成功。
- **AC-002-13**：给定执行期间编辑来源或生成器，执行前后指纹不一致时不提交该单元成功；提示来源已变化。运行中不得切换内容库；跨项目共用的全局目标也不能并发写入。
- **AC-002-14**：给定另一个库或工具写同一物理目标，开始写入前先使重叠记录失效；仅同库、同目标、完整输出集合与有效计划相同，且写入前已有可信 current 记录的候选，可在本次稳定成功且记录落盘后恢复原状态和时间。不同库/计划、部分重叠、失败/取消/中断/密钥变化、先前已失效记录均不恢复；其他不重叠目标不受影响。
- **AC-002-15**：给定修改来源、切页、切项目/库/工具、入库/回退完成、窗口重新激活或手动刷新，重新计算版本状态；晚返回的旧请求不覆盖新选择。
- **AC-002-16**：给定只查询状态，规范层和目标文件均无写入、无 vault 解密和网络请求；界面显示“已同步当前版本（未检查目标文件）”，现有规则 diff 结果与同步状态分开呈现。
- **AC-002-17**：给定单项 Skill 链接完成，不记录模块整体成功；卸载受管理链接后，即使来源未改，模块仍显示需重新同步。global 操作不更新 project 基线。
- **AC-002-18**：给定合成凭据和本地覆盖，状态 JSON、回执、日志与指纹输入清单中没有凭据或配置正文；首次查询不创建指纹密钥，显式同步创建本机密钥；成功与尝试记录保存派生 keyId。重启前原位替换为另一合法的 32 字节密钥后，查询显示 unknown/key_changed，不误判为来源变化；相同 keyId 下仅来源改变显示 pending/source_changed。密钥缺失、长度无效、记录缺 keyId 及运行中换密钥均不复用旧成功证据、不恢复等价候选。

## 5. 取舍与待决事项

已选方案：持久化来源版本记录，现有 diff 作为独立核验入口。2026-10-15 整改确认：保留工具记录并增加共享输出等价判定；保存由随机密钥派生的 keyId，查询时先核对密钥身份。内存标记不能跨重启；每次生成并比较全部目标属于更重的方案，本包不实现。
